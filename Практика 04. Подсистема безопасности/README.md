# Практика 4. Разработка подсистемы безопасности

Выполнила Терзи Эллия. Код в `portal/conference`: `permissions.py`, `security.py`, `forms.py`, `portal/config/settings.py`, проверки в `tests.py`.

## Что сделано

| Пункт задания | Как сделано | Где |
|---|---|---|
| Хеширование паролей | Django хранит пароль хешем PBKDF2-SHA256 с солью, открытого пароля в базе нет | `01_hesh_paroley_v_baze.png` |
| Защита от SQL-инъекций | все запросы идут через ORM Django, значения подставляются параметрами; в поле входа и в поиск ввела `' OR '1'='1` и `' OR 1=1 --`, вход не открылся, поиск пустой | `03_inekciya_v_login.png`, `04_inekciya_v_poisk.png` |
| Разграничение прав | роль это группа пользователя; гость уходит на страницу входа, участник на панели получает 403, статус меняет только администратор (на сервере, не только скрытой кнопкой) | `05_gost_na_paneli.png`, `06_uchastnik_403.png`, `permissions.py` |
| Проверка на сервере и в браузере | правила формы в `forms.py` (сервер) и атрибуты `pattern`, `minlength`, `type=tel` у полей (браузер) | `forms.py` |
| Защита сессий и cookie | `sessionid` с флагами `HttpOnly` и `SameSite=Lax`, сессия живёт 2 часа, на настоящем сервере включится `Secure`; формы с токеном CSRF; пять неверных паролей подряд блокируют вход на 5 минут | `07_blokirovka_posle_5_oshibok.png`, `08_cookie_sessii_v_devtools.png` |

Участник не может открыть чужие заявки: страница «Мои заявки» берёт из базы только заявки текущего пользователя. HTML в тексте заявки выводится как текст, шаблоны Django экранируют его сами.

## Проверка

Написала 25 тестов (`python manage.py test`): форма регистрации, форма заявки, доступ по ролям, инъекции, блокировка входа, токен CSRF, флаги cookie, экранирование HTML. Все проходят (`02_testy_25_iz_25.png`).

Хеширование и токен CSRF Django включает сам, я проверила, что они работают, и не отключала. Для скриншота 08 отправила запрос входа из консоли браузера через `fetch`: при обычной отправке формы запрос пропадает из списка из-за перехода на другую страницу.

## Результат

Подсистема безопасности работает: пароли хешированы, права разграничены, формы проверяются на сервере и в браузере, сессия и cookie защищены.
