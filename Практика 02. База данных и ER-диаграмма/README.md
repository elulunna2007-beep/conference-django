# Практика 2. Проектирование базы данных. ER-диаграмма

Выполнила Терзи Эллия. Проект на Django, база SQLite, код в папке `portal`.

## Сущности

Пользователя, группы и пароли Django хранит сам (таблицы `auth_user`, `auth_group`, `auth_user_groups`), пароль лежит там хешем. Поверх них добавила свои модели в `portal/conference/models.py`:

| Таблица | Поля | Что хранит |
|---|---|---|
| `conference_profile` | id, user_id, phone | телефон пользователя |
| `conference_event` | id, title, description, starts_at, city, place, image | мероприятие |
| `conference_status` | id, name, position | справочник: новая, назначено, завершено |
| `conference_application` | id, user_id, event_id, status_id, room, payment, comment, created_at | заявка участника |
| `conference_review` | id, application_id, rating, text, created_at | отзыв на заявку |

Роль пользователя задаётся группой: «Участники» или «Администраторы». Гость это человек без входа, в базе его нет.

## Связи

| Связь | Тип |
|---|---|
| пользователь и заявки | один ко многим |
| мероприятие и заявки | один ко многим |
| статус и заявки | один ко многим |
| пользователь и профиль | один к одному |
| заявка и отзыв | один к одному (отзыва может не быть) |
| пользователи и группы | многие ко многим, через `auth_user_groups` |

Ключи: у всех таблиц первичный `id`, внешние ключи помечены `FK`. Логин, название статуса и порядок статуса уникальные. На заявку можно оставить только один отзыв (`application_id` уникальный).

## Как проверила

Модели описала в `models.py`, команда `makemigrations` создала `0001_initial`. Справочник статусов и группы заполняет миграция `0002`. После `migrate` посмотрела таблицы командой `sqlite3 db.sqlite3 .tables`: все таблицы из диаграммы на месте, в `conference_status` три строки.
